## 1. 뉴스 크롤링 및 데이터 수집 파이프라인 개선

### 문제

500건 기사 처리 시 **단일 스레드 TTS 변환(건당 2.7초)** 때문에 파이프라인이 **22분간 블로킹**되는 문제를 확인했습니다.

### 해결

**Celery + RabbitMQ 기반 분산 작업 큐**를 도입하고, 기사 요약 · TTS · 썸네일 생성을 **독립 태스크로 분리**해 장애 격리 구조를 구현했습니다.

## 3. 캐싱 전략을 통한 API 성능 개선 및 비용 절감

### 문제

- 뉴스 갱신 주기(15분) 내에 **중복 DB I/O 부하**가 발생
- 매 요청마다 **임베딩 연산**이 발생해 API 응답이 지연

### 해결

- 기사 제목 · 내용 · TTS(GCS 링크)를 **Redis에 객체 단위로 캐싱**해 DB 접근 없이 즉시 응답하도록 설계
- 빈번한 **추천용 예시 문구의 임베딩 결과를 캐싱**해, 동일 문구 재요청 시 외부 API 호출을 제거
